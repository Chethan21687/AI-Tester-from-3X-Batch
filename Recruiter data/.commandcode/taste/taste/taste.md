# Taste
- Prefers Python + MongoDB for backend data storage when building React apps (instead of e.g. Node/Postgres or a paid cloud backend). Confidence: 0.9
- Prefers free / self-hosted / open-source solutions over paid services or paid hosting ("for free" when describing storage). Confidence: 0.6
- Uses Vercel as the hosting/deployment platform for the frontend, with the app's API served as Vercel serverless functions (an `api/` directory) backed by MongoDB — expects deployments to be carried out and verified to completion (build, deploy, then check the live URL and API endpoints). Vercel auto-deploys only from pushed GitHub commits, so uncommitted/unpushed local edits never reach the live URL — when the user reports a change missing on the deployed site, the assistant must check git/deployment state (commits, branches, remote) rather than assume a code bug. When the user says "commit it, move it to vercel app", they mean commit the fix AND get it live on the deployed Vercel site — deployment to the live app is the expected completion step, so the assistant should build, commit, deploy (e.g. via the Vercel CLI from the linked project dir, even without pushing to GitHub), and verify the live URL/bundle. Confidence: 0.75
- Prefers one-click batch scripts (e.g. `start-mongo.bat`, `start-backend.bat`, `start-frontend.bat`) to start the dev stack, and asks the assistant to run those scripts rather than raw commands. Confidence: 0.5
- Prefers the assistant to start the local dev stack (backend + frontend) for them and keep it running so they can verify in the browser: when the local URL won't load, the user reports the error via screenshot and expects the assistant to diagnose it (e.g. check `netstat` for listening ports) and launch the servers in the background, then report the ready URL — rather than just giving instructions for the user to run themselves. Confidence: 0.75

- Wants duplicate validation / data hygiene enforced at the data-entry points: Excel uploads should reject files containing duplicate candidate rows (matched on phone + email), and adding entities (e.g. recruiters) should prevent duplicates. Confidence: 0.7

- Expects the locally running app to be reloaded/restarted so code changes are actually live at the local URL — after changes, the assistant should restart the dev stack (killing orphaned processes on the ports first) and verify the new behavior end-to-end in the running app, not just leave the code updated. Confidence: 0.7
